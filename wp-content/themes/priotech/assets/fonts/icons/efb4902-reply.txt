while I am ok with either style (the first is my preferred because the space after ( makes the variable much easier to quickly read to me, and the extra new line takes up precious vertical space), when the changes are integrated with a patch that actually makes changes to the code makes the patch very 'noisy'

What I would suggest if you want to change the format (or that if your editor wishes to change the format, which is another issue), so to submit 2 commits.  One commit only does the formatting changes, and the other commit changes the code, so the actual changes are easy to pick out with a diff, and more importantly, a git blame/annotate is easier to find the actual logic change.  If I do a git blame and see a commit that says 'update formatting', I know I have to go to the previous commit to find the actual logic change.
